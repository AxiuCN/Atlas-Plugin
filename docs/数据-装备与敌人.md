> 本册由插件根 `AGENTS.md` 拆出，对应主文件的「四·3 武器 · 四·4 圣遗物 · 四·5 敌人/怪物 · 四·6 邦布」；主文件只留快速参考与文档索引。

## 3. 武器 / 光锥 / 音擎（共用 weapon.html）

| 项 | 处理 |
|----|------|
| GI 类型 | `list.type` / `detail.weapon_type`（**无 `list.weapontype`**）经 `weaponLabel()` → 单手剑/双手剑/长柄武器/法器/弓；TPS 武器 `ITEM_TPS_WEAPON` → 「枪」（全表 8 件：榴晶·四元素、影域特化榴晶、瓦尔萨格的日轮、莎塔娜娅的苍银、阿夏梅兹的千光）。进 hero 主标题下方小方框 |
| GI 属性 | 基础攻击力取 `list.atk`（满级）；副属性取 `detail.stats_modifier` 非 atk 项 × `levels['90']`，经 `giPropInfo()`/`formatGiProp()` 加「副属性 · 」前缀；**无副属性时键为 `fight_prop_none`（恒 0）须跳过**，否则露出原始键名 |
| GI 描述 | `detail.desc`（中文；`list.desc` 是未翻译英文不可用），`cleanMarkup` + 字面 `\n` 归一，置 hero 底部一行 `.hero-desc`（3 行截断）；源站无该字段则整行不显示 |
| HSR 命途 | `list.baseType` / `detail.base_type` 经 `hsrLabel()` → hero 小方框 |
| HSR 满级属性 | `detail.stats` 末档 `base_hp/base_attack/base_defence` + `_add` → `Math.round(base + 79×add)`（与 nanoka `list.atk` 全 169 条自洽） |
| HSR 文本 | 光锥详情无 `desc`/`story` → 不出故事栏，不引外部源 |
| ZZZ 特性 | `detail.weapon_type` | → hero 小方框（强攻/击破/异常/支援/防护/命破/锋御）；描述补充取一句话版 `desc3` 置 hero 底部 `.hero-desc` |
| ZZZ 满级属性 | `detail.base_property` / `rand_property` + `level["60"].rate` + `stars["5"]` | 主属性 = `value × (1 + (level[60].rate + stars[5].star_rate)/10000)`、副属性 = `value × (1 + stars[5].rand_rate/10000)`（即 ×2.5）——与 nanoka `list.atk` 全 100 件逐件一致（截断取整；`list.atk` 存的正是该满级值）。副属性标签加「副属性 · 」前缀（同 GI 武器页）；4 件锋御主属性为「基础防御力」 |
| ZZZ 音擎故事 | `detail.desc` | 完整故事（含 `#959595` 灰色引用）→ `type:'text'` 栏，置于**突破素材之后**；`desc`/`desc3` 为纯标点占位（5 件新音擎）时按空处理不显示 |
| 精炼 / 叠影 / 音擎天赋 | 三家形状不同（见下），统一由 `components/sections/weapon/refine.js` 的 `mergeRefineLevels(levels, prefix)` 合并 | **1~5 档合并成一段**：各档只有数值差异 → 合成 1 条（差异处写 `12%/15%/18%/21%/24%`，全档相同则只出现一次），并把差异数值按 `a/b/c/d/e` 用 `/` 连接；文本骨架不同的档位（原神「星锋剑」精炼1 多一句）→ 按**相邻同形状**分组、各组单独成条并标 `精炼1` / `精炼2-5`。**单组不显示等级标签**（标题只留效果名）。数据来源：GI `detail.refinement[k].desc`（已代入数值）、HSR `detail.refinements.desc`（模板 + `level[k].param_list`，逐档 `resolveHsrParams` 后再合并）、ZZZ `detail.talents[k].desc`（已代入数值）。切词先按 `<...>` 把标签整体切出（色号里的十六进制不会误判成数值），标签外文本再按 `\d+(?:,\d{3})*(?:\.\d+)?%?` 切数值 |
| 精炼合并的歧义处理 | 同一档文本里本来就有 `/` 分隔的多个数值（如雾切之回光「8/16/28%」），每个都随精炼变化时，合并后相邻多值槽之间只剩 `/`，会连成 10~15 个值的一长串 | 这类相邻多值槽**各自加圆括号**：`(8/10/12/14/16)/(16/20/24/28/32)/(28%/35%/42%/49%/56%)`。判定只在「两槽之间只有 `/` 文本」时触发：原文本自带的常量斜杠表（`持有1/2/3层`、`上限60/40点`）不加括号；ZZZ/HSR 把每个数值各自包在高亮 span 里的（如时光切片 `[20/23/26/29/32]/[25/…]`）靠高亮块本身分隔，也不加括号。全量：GI 8 件（织月者的曙色/雾切之回光/落霞/冬极白星/飞雷之弦振/最初的大魔术/白雨心弦/星鹫赤羽）、HSR 0 件、ZZZ 0 件 |

## 5. 敌人/怪物（monster.html，三游戏共用）

| 项 | 处理 |
|----|------|
| 共享数据层 | `model/monsterIndex/`（页面 builder 与未来的终局模块共用）。浅索引取 map.json 的 monster record 键——三游戏该键都是有效主 id（GI 是代表 child id、HSR/ZZZ 是 `detail.id`），零文件读取即覆盖终局绝大多数引用；深索引仅在查不到时按需读条目补全变体 id（GI 无 `detail.id`，只有 `child` 键；ZZZ 另有 `monster_info` 键）。对外：`getMonsterEntry` / `resolveMonsterId` / `getMonsterVariants` / `collectMonsterVariants` / `listMonsterEntries` / `hsrCampLabel`；等级表在 `levelTable.js`（星铁 `HardLevelGroup`，整页惰性读一次） |
| 终局 id 归一 | 星铁末日幻影的 `boss_monster_id` 形如 `100401401`，实为「怪物 id × 100 + 变体序号」→ `resolveMonsterId` 按 `floor(id/100)` 回查（全部 68 个引用 100% 命中，如 `1004014`「无望冽风的幻灭者」）。其余引用直接命中：HSR 混沌 `npc_monster_id_list` 61/61、ZZZ 式舆 `monster_list` 147/147、GI 深境螺旋 room 193/261 |
| 同名折叠 | 索引期按 (pageKey, name) 折叠：主条目按「有 detail → 图多 → 键小」选取（组内位置不变），其余记录的路径记入新字段 `variantPaths[]`、其 id/文件名别名并入主条目（`%1002012` 仍可命中）。HSR 628 条 → 373 条、ZZZ 306 → 238、GI 585 → 577。**修掉了原先顺带折叠的有损行为**：那时走角色「多形态」通路，同名只留一个 `variantPair`，其余变体数据直接丢弃 |
| GI 面板 | `child.base` 是**成长系数不是面板值**：面板 = `base × 该变体 child.prop[].grow_curve 指定的曲线(103)`（世界等级 9，怪物等级 93~103 取满级 103），标签写成 `生命值 (Lv.103)`；元素精通无曲线，按原值出且不标等级。曲线表 `resources/data/gi-monster-curve.json`（官方 MonsterCurveExcelConfigData 精简版：13 种曲线 × 200 级，18.8 KB，生成脚本 `本机工作区的生成脚本（见 `docs/private/`，不入库）`） |
| GI 曲线识别 | 同一「怪物」的不同变体会声明不同曲线（`GROW_CURVE_HP` 与 `HP_2` 在 103 级相差 55%），**必须按变体取**。反推验证：深境螺旋 `room.first/second[].hp` ÷ 本式 = 该层 `hp_ability` 的常数，6 期 × 全怪物零偏差（`HpUp_Lv3` → 2.00000、`HpUp_Lv4` → 2.50000、`Stage12_New2` → 3.75000）。**该系数随版本增长**（nanoka 重抓时老期数一并重算），故只用于识别曲线，绝不参与计算——大世界无环境系数（= 1.0）。旁证：`base.def=500` × `GROW_CURVE_DEFENSE(103)=2.03` = 1015 = `5×103+500` |
| GI 栏位 | hero 短描述取 `detail.title`（与条目名相同视为占位不出；「门扉前的弈局」被源站抓成「愚人众执行官第八席」，由 `resources/patch/data/items/简体中文/原神/敌人/未分类/门扉前的弈局.json` 补丁改为「并非「弈局」的执棋者」）；分类小方框 `codex` 12 类；**元素伤害抗性**用 `child.sub_hurt`（承伤系数，全 0 表示无抗性则不出）；**特殊称谓**用 `special_names`（62%），置于元素伤害抗性之后；图鉴描述 `detail.desc` 独立段落；掉落 `detail.reward`（48%）——名称先查 `item` 页、未命中兜底 `item_all`（「冒险阅历」102 /「好感经验」105 只登记在 item_all，item 页 2095 条里没有），图标按 reward 项自带的 `icon` 资源名直查 gallery（比按 id 直拼可靠），`400xxx` 是「套装 × 部位 × 星级」抽象 id（`item`/`item_all` 里都没有条目），按 icon 反查 artifact 页部件名并缀星级（如「战狂的蔷薇（四星）」，星级只标圣遗物）；排序走 `sortMatItems`；**无技能数据**。225 条野外生物（ANIMAL/FISH/CRITTER/AVIARY）无 `child` → 只出描述与分类；2 个变体声明 `GROW_CURVE_NONE`（裂空的魔龙等）算不出面板 |
| HSR 面板 | = `detail.<stat>_base` × `HardLevelGroup(group, 等级)` 的比率（`child[].hard_level_group` 全 2648 变体均为 1），基准等级 **95**，标签写成 `生命值 (Lv.95)`；速度/韧性/效果抵抗没有等级比率，按原值出、不标等级。表加载见 `model/monsterIndex/levelTable.js`（整页惰性读一次）。`elite_group` 是终局（混沌/末日）按难度二次缩放的键，不属于怪物自身面板，**不参与** |
| HSR 栏位 | hero 小方框三项：**阵营 → 评级（直接用数据里的英文档位码 MinionLv2/Elite/LittleBoss/BigBoss…）→ 弱点**（形如 `弱点：火 风 虚数`）；阵营是手写表 `HSR_MONSTER_CAMP_LABEL`（数据只有 1~18 数字），**camp 为空与未登记都归「其他」**（378/628 条为空），未登记 id 另外告警一次；**弱点与属性抗性**栏保留（弱点 + 逐项抗性）；技能 `child[].skill_list`；掉落取 `detail.drop` 末档 `display_item_list`（与养成素材同一排序口径 `sortMatItems`）。少数怪（角色的「幻象」版，如卡芙卡 / 资深员工·组长）技能描述带 `#N[fmt]` 参数占位符但**怪物侧没有 param_list** → 只出技能名、不出描述 |
| ZZZ 面板 | = `stats.<属性>` × `curves.<属性>.curve[等级-1] / 100`，基准等级 **70**，标签写成 `生命值 (Lv.70)`；面板六项：生命值 / 攻击力 / 防御力 / **冲击力**（`stun`，不是「失衡值」）/ 失衡伤害倍率（`stun_damage_taken_ratio` ÷100）/ 失衡持续时间（`stun_reset_recover_cd` ÷100 秒）。式舆/危局等终局还会在曲线上再乘一层环境系数（实测 lv25 → 1.2187、lv28 → 1.4883），属终局口径，本页不参与 |
| ZZZ 栏位 | hero 短描述 = `card_quote`（卡牌引言）；小方框 = 族群（`group_desc`）+ **弱点** + **抗性（只列属性，不带数值——数值在下方「弱点与抗性」栏）**；星级走 hero 行右侧（`zzzRankOf` → S/A/B/C）；**弱点与抗性**栏保留并列出具体数值；战斗提示 `card_skill_desc`；**不显示「获取方式」**（`card_obtain` 是游戏内卡牌解锁提示，非怪物资料）。`element_abnormal`（异常积蓄）的键是内部属性 id、全库无名称映射，不出 |
| 变种个体 | 全部变种各占一行（标题带总数，如「变种个体（34）」），name = 内部代号（GI `monster_name` / ZZZ `code_name`）或 `ID <id>`（星铁，此时行内不再重复 ID）；行内容 = `ID · 分类 · 全部属性（不带等级标注）· 弱点 · 抗性`，用 ` · ` 分隔。**原神抗性只列非 10%（默认值）的项**（如嵴锋龙只出「岩 50%」），星铁/绝区零全列。单条最多的是 HSR「无尽寒冬之槊」100 个变种 |
| hero / 模板 | hero 顺序 = 标题 → 小方框（`hero-info`）→ 短描述（`hero-desc`）；`monster.html` 补了这三个分支与 `text`（`.desc-block`）、`materials`（`.material-grid`）并链接 `detail.css`；hero 行的星级只对绝区零出（GI/HSR 的 `meta.rarity` 是「未分类 / 二星」这类目录名） |


## 6. 邦布（bangboo.html，仅绝区零）

| 项 | 处理 |
|----|------|
| 属性表格 | `detail.stats` + `detail.level[6]`：生命值 / 攻击力 / 防御力 / 冲击力 / 异常掌控 = `trunc(基础 + 59×成长/10000 + 最高突破档累计)`——**邦布成长字段是 `hpupgrade` / `attack_upgrade` / `def_upgrade`**（命名与角色不同），公式同源，已用游戏内 Lv60 攻击力 8863（「墨丘利」）核对。全表恒定项不列（`endurance`180 / `crit`500 / `crit_dmg`5000 / `pen_ratio`0）；无 `element_mystery`（异常精通）与 `sp_recover` |
| 突破加成 | `detail.level[6].extra`（暴击率 / 暴击伤害的累计值，38 只邦布逐档链完全相同）→「突破 · X」小格，`%` ÷100（4500 → 45%）；值为 0 不列；3 只无 `extra`，伊埃斯无 `level` 表 |
| 三招技能 | `detail.skill.a/b/c` = 主动技 / 额外能力 / 连携技（**档数各不相同**：a 10 档、b 5 档、c 10 档，8 只没有 c）→ 每招一张卡（`name` 取数据招式名、`tag` 取类别）；表取**末尾 7 档**（a/c 即 Lv4~Lv10，同角色/星铁口径）；各级同值的行（「冷却时间 25秒」）入固定小格 |
| 技能取值 | 每档 `param` 按 `|` 拆段：含 `{Skill:<id>, Prop:<n>}` 的段（含复合公式 `{A}*2+{B}`、`{{A}/3}*3`、`{{A}/100}*140`）查 `detail.skill_prop` 得 `main + growth×(Lv-1)`，`%` ÷100（与角色同一约定，旁证是数据自带文本段同为该量级）；不含引用的段是数据已按档算好的文本（`25秒` / `45%`），原样输出 |
| 单元格分段 | `_splitSegs()` 把文本按「数值原子 / 文字原子」切段（`8.4%生命值` → `8.4%` + `生命值`、`0.26点/秒` → `0.26` + `点/秒`），段间由模板的 `<wbr>` 提供换行点——等宽单元格（7 档表每格内容宽仅 86px）里整串不折会压住相邻格（**实测 60 处，最大溢出 46.5px**，用户报的艾瑞儿「8.4%生命值」即此类）；纯数值（`1722.6%`）本身无断点，仍留 ≤12px 重叠（**用户确认不处理**）。角色页实测 0 处溢出，故只改邦布、不动共享 `toSegs()` |
| 未求值公式 | 数据自带的 `[表达式]`（`[4.4+自身等级*0.08]点`）变量是**自身等级**（不是技能等级、也不是角色的 `{CAL}` 机制），同一行只有常数项随档变化；整串约 230px 无处安放 → 该行整行改走固定小格（**取末档**，同满级口径），不占表格列，方括号原样保留。4 只邦布有：巴特勒 / 气压布 / 骑士布 / 艾丝弥小姐（骑士布「攻击力提升」连系数也随档变：`[20+…*1.2]` → `[40+…*2]`） |
| hero / 其他 | hero 只出一句话（`detail.desc`；与条目名相同的占位条目不出），无小方框（数据里没有属性/特性/阵营字段）；素材栏「突破素材」；`talent` 字段不存在（旧实现的「影画」段是死代码，已删）；`bangboo.html` 的技能参数块与 `character.html` 对齐（固定小格 + 单表/续表 + 分段渲染） |
