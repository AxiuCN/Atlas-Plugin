# 别名对外 API 与接入指南

> **Atlas-Plugin 除图鉴查询外，也承担别名基础设施角色**：把 miao-plugin / ZZZ-Plugin / Atlas 预设 / 用户自定义**四层别名来源**合并成一张表，并对其它插件开放只读查询。
> 目的是让接入方不必再解析同一批上游文件、不必各建一份表、不必各挂一套 watcher —— 一处维护、多处复用。
> 契约版本见 `modules/aliasApi.js` 的 `ALIAS_API_VERSION`（形状不兼容变化时 +1）。

## 一、能力边界

| 提供 | 不提供 |
|---|---|
| 四层来源合并（外部预设 < miao 自定义 < Atlas 预设 < Atlas 自定义） | 业务侧解析（图库目录判定、索引评分、页面路由） |
| 归一化（空格 / 六种间隔号 / 括号引号 / 大小写） | 别名**写入**（仍只有 Atlas 的 `#图鉴别名设置` 等命令） |
| 按游戏过滤、多值候选、热更新、版本号 | 跨插件全局注册表 / 单例 |
| 只读查询，**永不抛错**（异常只 `logger.warn` 并返回空结构） | 缓存副本（接入方不得自己再存一份表） |

## 二、API（`modules/aliasApi.js`）

| 函数 | 返回 | 说明 |
|------|------|------|
| `getAliasMap(gameId?)` | `Map<归一化名, [{value, game, source}]>` | 只读，返回 Atlas 的缓存实例，消费方视为 immutable；未知 `gameId` 退化为全量 |
| `resolveAlias(name, gameId?)` | `{ key, candidates: string[], primary: string\|null }` | 表是**双向注册**的，`candidates` 是「对侧名称」**不含方向**；空/缺失入参返回空结构 |
| `expandKeyword(keyword, gameId?)` | `{ raw, key, alias }[]` | 原词 + 别名变体（按游戏过滤、去重） |
| `getAliasVersion()` | `number` | 每次重建 +1；接入方的派生缓存据此失效 |
| `getAliasStatus()` | `{ version, keys, entries, games }` | 排障 / 接入自检 |

`gameId` 取 `gi` / `hsr` / `zzz`；**不缺省按游戏过滤**时，跨游戏同名别名会一起返回，由接入方自己裁决。

## 三、最小接入示例

```js
// 必须是动态 import + try/catch：
// 静态 import 在「Atlas 未安装 / 被禁用」时会让你的整个插件加载失败，降级路径就没机会执行。
let aliasApi = null
try {
  aliasApi = await import('../../Atlas-Plugin/modules/aliasApi.js')
} catch {
  logger?.warn('[YourPlugin] Atlas 别名门面不可用，使用本地兜底')
}

const hit = aliasApi?.resolveAlias(userInput, gameId)   // { key, candidates, primary }
const target = hit?.primary || userInput                // 未命中 / 不可用 → 用原输入继续
```

## 四、接入约定（必须遵守）

1. **动态 import**，不要静态 import（理由见上）。
2. **传 `gameId`**：接入方若同时服务多个游戏，命令侧必须把当前游戏传进来，否则跨游戏同名的候选会混在一起。
3. **不缓存副本**：每次调用即可（表在 Atlas 内是缓存实例，查询是 O(1)）；确实要长期持有派生数据时，用 `getAliasVersion()` 比对，版本变了就重建。
4. **watcher 二选一**：Atlas 首次加载会自己挂热更新监听（目录树 + cfg 文件级）。接入方**不要**再挂自己的那套，否则同一批文件被监听两次、每次保存重建两次。只有在「Atlas 不可用」的降级分支里才启用本地监听。
5. **结果要过自己的业务裁决**：别名表不记录方向（标准名 ↔ 别名互为键），`primary` 只是「第一条候选」，接入方要结合自己的数据源（目录、索引、页面类型）判断最终用哪个。
6. **降级路径必须存在**：Atlas 是可选依赖。接入方要么保留自己的最小实现（并标注"冻结、仅兜底"），要么在不可用时直接原样返回输入、不影响主功能。

## 五、已有接入方：ProfileImg-Plugin（参考实现）

ProfileImg 面板图插件已按本指南接入，可作为完整范例：

| 做法 | 说明 |
|---|---|
| 门面优先、本地兜底 | `modules/alias.js` 先走 Atlas 门面，未命中或不可用才用本地冻结实现 |
| 保留自己的目录能力 | `resolveRoleName(name, game)` 仍做「目标目录存在」校验 + 精确/大小写/模糊回退（这些是**图库**语义，门面不提供） |
| watcher 二选一 | Atlas 可用时不调用自己的 `watchCustomAliasFiles()` |
| 兜底冻结 | 本地实现保留但不维护，顶部标注；自建 `alias-fallback` 套件钉住其行为 |
| 来源可观 | 启动打印「别名来源：Atlas（v…）」或「本地兜底」 |

其细节见 ProfileImg-Plugin 的 `docs/模块-别名.md`。

## 六、两条路径的差异（接入方文档应写明）

| 维度 | 本地兜底（各插件自建） | Atlas 门面 |
|---|---|---|
| 表规模 | 通常只含自己需要的类别（如仅角色，约 1900 条） | 全量（约 3100 条，含武器 / 圣遗物 / 绝区零） |
| 多值 | 多为单值（后写覆盖） | 同一键可挂多个候选（含跨游戏） |
| 分隔号 | 各写各的（常见只做 `toLowerCase`，`•`/`·` 不互通） | 六种间隔号统一去掉，`•`/`·`/无分隔号等价 |

因此「装了 Atlas / 没装 Atlas」同一输入可能解析结果不同——这是可选依赖的固有代价，接入方应写进自己的文档。

## 七、验证

接入方施工后至少确认：

1. 装了 Atlas：命令行为与接入前一致（同一输入同一结果），启动日志显示来源为 Atlas
2. 临时把 Atlas 目录改名（模拟未安装）→ 启动日志显示「本地兜底」，命令仍可用
3. 恢复目录并重启 → 来源回到 Atlas
4. 自己的回归套件全绿（兜底路径的断言建议单独一套，且**不依赖** Atlas）

## 八、不做

- Atlas **不**替接入方改代码、不代写其测试
- 接入方**不**复制 Atlas 的表实现（需要能力就提需求，扩展门面）
- 不引入跨插件全局注册表 / 单例
