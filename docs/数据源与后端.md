# 数据源与后端

> 本册由插件根 `AGENTS.md` 拆出，对应主文件的「二、数据后端」；主文件只留快速参考与文档索引。

## 一句话

数据引擎是子模块 **Hesperides**（`tool/Hesperides/Hesperides/`，仓库 `AxiuCN/Hesperides`），
多源采集：**nanoka**（`static.nanoka.cc`）、**玉璃**（`json.alioth.wiki`）与**Lunaris**（`api.lunaris.moe`）。
引擎侧**各源对等**——可抓的页面都抓、重叠部分不裁剪，谁更权威不由引擎判断。

**本插件只消费其中一部分**（这是插件的取舍，不是源的属性）：

| 用途 | 取自 | 原因 |
|---|---|---|
| 内容索引（`index.json` 的页与条目） | **nanoka 全量页** | 三游戏覆盖最全，绝区零只有它有 |
| 终局期与期时间（`periods.json`） | **玉璃** | nanoka 那边 hsr 四个终局页的 `begin`/`end` 全为空串，期时间实际取不到 |
| （未消费） | **Lunaris** | 原神目录与中文详情等 14 个频道，引擎已接入但插件暂不取；需要时在引擎目录单独抓：`node src/cli.mjs --channels lunaris:gi:character --with-details --images` |

运行期**纯文件读取**：不走网络、不依赖 Redis。

旧引擎 `nanoka-atlas-backend` 已退役并从仓库移除（子模块条目删除、数据目录清空），插件**没有任何旧数据回退路径**。

## 产物（`<插件根>/tool/Hesperides/Hesperides/data/`）

| 文件 / 目录 | 内容 |
|---|---|
| `index.json` | 频道状态 + `games.<game>.sources.<source>.pages.<page>`（`ids` / `records` / `entries`） |
| `periods.json` | 终局各玩法的期表，按 `games.<game>.<source>.<page>` 分组 |
| `manifest.json` | 增量判据（hash / lastModified / 版本 / 期列表），每频道结束即写，可断点续跑 |
| `image-failures.json` | 失败候选 URL，下一轮默认不再探测 |
| `upstream/nanoka.json` | 上游根清单快照（`latest` / `live` / `new`），`#版本新增内容` 的数据源；只有提供根清单的源才有这个文件 |
| `records/<game>/<source>/<page>/<id>.json` | 源原始记录；单文件频道（如 `diff`）落 `__index.json` |
| `imagerefs/<game>/<source>/<page>.json` | 该页记录级图片引用（插件按页加载，LRU 常驻 8 页） |
| `images/<game>/<目录>/<文件>.<ext>` | 图片文件（镜像 CDN、按资源名去重、与源无关） |

**源是路径维度**：同一 game 下玉璃与 nanoka 有同名页（`weapon` / `monster` / `item`），带 `<source>` 才不会互相覆盖。

## 插件侧读取

| 模块 | 职责 |
|---|---|
| `model/Hesperides.js` | 产物客户端：`index.json` / `periods.json` 缓存（按 mtime）、期表映射、单文件频道、图片引用按页 LRU |
| `model/HesperidesRepository.js` | 合成路径 `hes/<game>/<source>/<page>/<id>.json` ↔ 记录，适配成 `{meta, content:{list, detail}}`，并把图片还原成 `meta.images` |
| `model/HesperidesIndex.js` | `entries` → 搜索索引（只取 `nanoka` 源） |
| `model/ItemAssets.js` | 素材名称 / 图标（`entries` 的 `name` / `icon`）、按资源名找图 |
| `model/AtlasRepository.js` | 记录读取 + 补丁套用 + 记录缓存；非合成路径一律视为不存在 |

- 合成路径**不进磁盘**，只作 key：搜索、构建器、补丁层签名都不变
- 记录缓存按 `size|mtime` 判活，`#图鉴更新` 重抓后自愈
- `resolveRecordImage()` 只把 `images/` 前缀拼到 Hesperides 产物根，不再有旧 `gallery/` 回退

## 抓取

**运行期范围固定为 nanoka 全部页 + 玉璃终局 7 频道**（`model/AtlasUpdater.js` 的 `runtimeChannelIds()`）。
玉璃的非终局页与 nanoka 同名同页（`weapon` / `monster` / `item`），插件既不用、抓了也是重复劳动，所以不抓。

抓取时机由插件决定：`#图鉴初始化` / `#图鉴更新` / 每日定时任务；锁在 `data/_scraping.lock`（`wx` 原子创建）。
版本比对取 nanoka 根 `manifest.json` 的 `latest`（本地版本读产物 manifest 里 `character` 频道的 `version`）。
手动抓参见 [`../tool/Hesperides/Hesperides/README.md`](../tool/Hesperides/Hesperides/README.md)：

```bash
node src/cli.mjs --all --no-textmap --with-details --images   # 全量（首次建库）
node src/cli.mjs --all --no-textmap --with-details --images --mode incremental
node src/cli.mjs --export                                     # 只重建 index/periods
```

## 子模块未就绪时

插件**不会因为子模块缺失而加载失败**：`model/AtlasUpdater.js` 用动态 `import()` 读子模块的频道表，
拿不到时回退到产物 `data/manifest.json` 的 channels 键。

这是必需的——同步子模块的代码本身就在这个文件里，静态 import 会让全新安装变成死锁（插件加载失败 → 用户连 `#图鉴初始化` 都发不出去）。回归见 `test/submodule-independence.test.mjs`。

## 图片去重

同一条图片资源可能被多个源引用（nanoka 与 Lunaris 给 `.webp`、玉璃给 `.png`）。引擎的候选按**格式体积**排序
（webp → png），与记录所属源无关，所以两边命中的是同一个 URL、落盘路径一致，**不会存两份**；玉璃独有的资源才回落到 png。

升级前抓过的数据可能已经存了重复：

- **不影响功能**，只是多占空间
- 抓图时按「资源键」判活，磁盘上已有该资源（哪怕别的格式）就直接复用，**不会因为候选顺序变了而重下**
- 每次抓取结束后自动清理（`config.yaml → imagePrune.enabled`，默认开）：只删同目录同基名的多余格式，并同步修正图片引用；无重复时短路，零额外开销
- 手动执行：`node src/cli.mjs --prune-images`（预览）/ `--prune-images --yes`（执行）

## 老用户升级（1.4.x → 1.5.0）

1. 拉取后 `.gitmodules` 已无 `tool/nanoka-atlas-backend` 条目，但 **`git pull` 不会删除子模块工作目录**
   （它带自己的 `.git`，对主仓库是未跟踪内容），磁盘上会残留几百 MB 旧数据与旧代码
2. 插件启动时会调用 `runLegacyCleanup()`（实现在 `model/LegacyCleanup.js`）清掉三处残留：
   `<插件根>/tool/nanoka-atlas-backend/nanoka-atlas-backend/` 工作目录、`.git/config` 里的 `submodule.tool/nanoka-atlas-backend/…` 段、
   `.git/modules/tool/nanoka-atlas-backend/` 旧仓库对象。**只处理这个退役路径**，`.gitmodules` 里仍在用的子模块不碰；
   外层目录里用户的 `.dsh/` 等不入库内容不动。该清理是**临时机制**（连同 `model/LegacyCleanup.js` 整份文件，计划 2026-12-31 后删除）
4. Hesperides 子模块会在启动时自动 `git submodule update --init --remote`；数据要重新抓一次（`#图鉴初始化`）

## 已知口径

- 玉璃的 `Ver` 是**覆盖版本**，不换算成开启版本；期归属由 `begin` 判定
- 玉璃 hsr 四个挑战玩法的期日期由 Hesperides 在抓取时补出（上游记录无 `begin/end`），插件直接读 `periods.json`，不再自行估算
- 图片按资源名去重：实测 17,209 个文件覆盖 10 万+ 引用；候选常 2~6 个 URL，命中即止，全失败落占位图
