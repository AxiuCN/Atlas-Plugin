# 数据源与后端

> 本册由插件根 `AGENTS.md` 拆出，对应主文件的「二、数据后端：nanoka-atlas-backend」；主文件只留快速参考与文档索引。

`tool/nanoka-atlas-backend/nanoka-atlas-backend/`，fork `https://github.com/AxiuCN/nanoka-atlas-backend`（上游 MOPELotus），把 nanoka.cc 图鉴抓成本地 JSON + 图库。

- **fork 自有改动**：`src/scrape.mjs: resolveRequestedVersion` 未传 `--versions` 时默认 manifest.latest（主页 SvelteKit 预取版本常滞后，曾致新角色静默缺失）；带 available 发布窗口护栏。插件所有抓取路径都不带 `--versions`，自动受益。
- **命令**（子模块目录下，yarn 4）：`corepack yarn scrape`（默认刷新 JSON + 增量图）、`scrape:full`、`scrape:incremental`、`scrape:no-images`、`scrape:check`、`scrape:verify`、`versions`、`audit:missing-images`、`report:missing-images[:filtered]`。限定范围：`node src/scrape.mjs --game hsr --locale zh` / `--locales zh,en --no-images` / `--versions hsr=4.3.51,gi=6.6.52`。
- **路径解析（关键）**：`meta.images[].localPath` 相对 **backendRoot**，不是 `data/`：

```
backendRoot = tool/nanoka-atlas-backend/nanoka-atlas-backend/
dataDir     = backendRoot/data/
localPath   = gallery/gi/Skill_A_01.webp      ← 相对 backendRoot
```

- **图片策略**：增量模式下本地已有且远端元数据未变则复用；全候选 404 → `gallery/_placeholder/unknown.svg` 占位；超时/5xx 记 `status:"error"` 不降级占位；占位与 error 不写入 `image-cache.json`，下次重试；模板名（`..._{0}`）不下载。
- **目录**：`data/{map.json, gallery-index.json, image-cache.json, items/<语言>/<游戏>/<子页面>/<分类>/<条目名>.json, audits/}` + `gallery/<game>/`。条目 JSON = `meta`（含 `images[]`）+ `content.list` + `content.detail`；map.json 只存索引与 path。
- 网络参数（env）：`REQUEST_RETRIES=4`、`TEXT_TIMEOUT_MS=60000`、`JSON_TIMEOUT_MS/IMAGE_TIMEOUT_MS=120000`、`IMAGE_RETRIES=4`。依赖仅 cheerio。
- **抓取锁**：`data/_scraping.lock`（内容 `{pid, time}`），`_acquireLock()` 用 `flag: 'wx'` **原子创建**（存在即 EEXIST）——早先 `existsSync → writeFileSync` 两步有并发双进窗口，实测 8 进程可**全部**通过检查；创建失败时区分「活跃锁」（拒绝）与「残留锁」（pid 已死 / 超过 `LOCK_TTL_MS` → 清理后重试一次）。模块加载时 `_cleanupStaleLock()` 清残留并 kill 残留进程树（`taskkill /PID <pid> /T /F`）。
