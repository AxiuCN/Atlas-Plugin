# 架构与分层

> 本册由插件根 `AGENTS.md` 拆出，对应主文件的「三、架构与分层」；主文件只留快速参考与文档索引。

```
Atlas-Plugin/
├── index.js              # 单入口：配置 → syncSubmodule → 预加载索引 → Promise.allSettled import apps/*.js
├── apps/                 # atlasShortcut(-99999) / alias(8000) / updateLog(9000) / status / help / admin / atlas(~10000)
├── modules/              # atlasQuery.js(handleQuery/handleSpecialQuery)
├── model/                # AtlasService(搜索/索引/loadRecord/resolveRecordImage) · AliasLoader · CustomAlias
│                         # LinkResolver(GI LINK) · MiaoParams(HSR 参数名) · AtlasUpdater(子模块/抓取) · VersionDiff(版本更新记录) · itemIndex/ · monsterIndex/
├── components/           # config · constants · render · queryUtils · protagonist · patch · util · materials · sections/
│   └── sections/         # index(注册表) + character|weapon|relic|monster|bangboo|item（各含 index + 游戏分文件）
├── resources/            # alias/ · patch/ · atlas/*.html · common/*.css + font/
├── config/               # config.yaml.example + alias/（用户自定义，git-ignored）
├── guoba/ + guoba.support.js + defSet/config.yaml
├── test/                 # 回归套件（入库）：_helper.mjs 公共设施 · run.mjs 运行器 · fixtures/fake-git/ · *.test.mjs
├── tool/nanoka-atlas-backend/    # 图鉴数据引擎（submodule，外层 README 入库）
```

**builder 注册表**（`components/sections/index.js`）：character→character.html、weapon/lightcone→weapon.html、artifact/relicset/equipment→relic.html、monster、bangboo、item；无 builder 的 pageKey 走 detail.html（rawFields）。

**模板路由**（`components/render.js` selectTemplate）：`type=list`→list.html；special+page_list→achievement.html；special+page_detail→challenge.html；exact 且 pageKey 有专用模板→对应模板；其余→detail.html。**有意把列表结果路由到详情模板**：tpl≠list 时 atlas.js 为首条加载完整记录并构建详情，属 UX 特性非 bug。

**数据流**：`#/*/%关键词` →（带后缀时先由 atlasShortcut 抢占）→ `handleQuery` → `search()` 得 exact/list/special → `loadRecord()` → `buildDetailData()`（builder）→ `selectTemplate` → `renderAtlas` → `e.reply(segment.image)`。查询链路异常**只回通用文案**（`modules/atlasQuery.js` 的 `QUERY_ERROR_REPLY`），异常名 / 绝对路径 / 堆栈只进日志，不回显给用户。

**分层**：apps 事件绑定；model 数据访问（map/索引/条目/LINK/itemIndex）+ 别名读写；modules 业务编排（可整体替换搜索方式）；components 共享工具与 sections builder；resources 模板与样式。
**import 约定**：同目录 `./`、同层 `../`、跨层 `../../<dir>/`。
**配置三层**：`defSet/config.yaml`（锅巴模板，`${atlas_priority}` 占位）→ `config/config.yaml.example`（入 git）→ `config/config.yaml`（运行时，git-ignored）。`getPluginConfig()` 逐级兜底并 `deepMerge` 默认值。配置段：priority/renderScale、autoUpdate、alias(set/del/list 权限)、notifyGroups/notifyMode。

## 启动编排（`model/startup.js`）

`index.js` 载入时的真实顺序：

- ⓪ `cleanupLegacyCodexDir()` —— 同步执行，清除攻略模块剥离前遗留的 `<插件根>/tool/Character-Codex-Data/`（**临时机制**，2026-12-14 后连同调用点一起删除）
- ① `syncSubmodule()` —— **不 await**：git 可能拉到 120 s，而框架 `plugin_load_timeout` 只有 60 s，await 会让「首次安装」直接判插件加载超时
- ② `reloadIndex()` —— 立即用当前磁盘数据建索引，第一次查询就能用；失败只告警（首次查询会惰性重建）
- ③ sync 报告「确实切换了子模块」（`ok` 且非 `skipped`）→ 再 `reloadIndex()` 一次

③ 是必需的：②可能在 git checkout 期间读到**同步前**的 map.json，而 `ensureIndex()` 只判 `if (mapCache) return`，那份旧索引会被固化到进程结束——只能靠 `#图鉴更新` 或重启恢复。

编排本身不含业务：`sync` / `reload` / `log` 都可注入，因此在**没有图鉴数据**的环境也能完整测试（`test/startup-lifecycle.test.mjs`）。
