# 数据口径：搜索与角色

> 本册由插件根 `AGENTS.md` 拆出，对应主文件的「四·1 搜索与索引 + 四·2 角色页」；主文件只留快速参考与文档索引。

## 1. 搜索与索引

索引期额外处理：GI `artifact` 条目 name 是数字 ID，`ensureIndex()` 读 JSON 把 `list.set[].name.zh` 注入别名，使套装名可被 Phase 1 命中；多形态角色按属性派生变体名，男女折叠为一条（另一形态路径记 `variantPair`），族名只挂「族名归属形态」（无属性形态优先 → 旅行者；否则首个 → 开拓者·毁灭、三月七·存护），其余形态挂 `<属性>主` / `<属性><族名>` 等变体别名，避免整族同分导致 `#旅行者` 落到排序首条。
加分：PAGE_PRIORITY（角色 240 > 武器 220 > 圣遗物 210 > 挑战 200 > 邦布 120 > 敌人 110 > 物品详情 30 > 物品 20 > 摆设 10）+ 有图 +5 + 原名相等 +20。
Phase 2：加载前 `maxResults*5` 条，在 title/description/facts/sections 二次评分（精确 +80 / 包含 +35）；Phase 3 全文扫描；Phase 4 递归找文件名匹配的 JSON。
**全文兜底必须扫补丁后的内容**：`findDetailFallbackMatches()` 对高优先级条目（PAGE_PRIORITY ≥ 180）做子串匹配时，**有数据补丁的条目走 `loadRecord()` 的序列化文本**（补丁会改写甚至删掉上游文本，如把占位「菲谢尔专用」换回官方描述），无补丁的才读原文快路径。否则补丁层在搜索链路上失效：`#皇女圣遗物` 会经别名反查展开出「菲谢尔」、命中 15005 如雷套已被改掉的上游占位文本，消息被吃成如雷套页（实测命中分 210+120+0=330）。

**索引期形态族闸门**：只有「原神/星铁的角色页」「名字带 `·男性`/`·女性`」「主角族名（旅行者 / `{NICKNAME}`）」三种情况才 `loadRecord()` 派生变体名——物品/卡牌/套装页里的大量同名条目**不是**多形态，早先按 `familySize > 1` 一律读 JSON 会让一次索引构建解析上万个条目（实测 11,882 次 / 10 s，收紧后 136 次 / 0.4 s，且索引内容逐字节不变）。同名条目的折叠与 id/文件名别名合并由独立的 `duplicated` 标记控制，与"是否读 JSON"解耦。

**进程内缓存（读盘口径，改动时注意）**：`loadRecord()` 带 300 条 LRU（键 = 路径 + `size|mtime` 签名，命中即自愈；缓存的是**套过补丁**的实例）；全文兜底的可检索文本另有按字节限额的归一文本缓存（默认 32 MB，覆盖当前高优先级条目全集约 29 MB——**低于工作集会因 LRU + 固定扫描顺序抖动到 0 命中**，实测重复查询由 ~0.6 s / 500+ 次读盘降到 ~0.05 s / 0 次）；两者都由 `reloadIndex()` 清空，因此**补丁文件改动同样只在 `#图鉴更新` / 重启后生效**。诊断开关 `ATLAS_SCAN_FREEZE=1` 会把记录在入缓存时深冻结，调用方一旦写回立刻抛 `TypeError`（防共享实例被污染，见 `test/record-cache.test.mjs`）。

| GI LINK | 技能/固有天赋/命座 desc 内 `{LINK#N/S}` | `resolveLinks` 高亮 + 收集 refs，去重后单列「相关效果/规则术语」栏（技能卡内不内嵌）；`cleanMarkup` 清 `<color>` 残留（曾致冰属性高亮变灰） |
| HSR hero | `list.baseType` / `list.damageType` | `hsrLabel()` 映射命途与属性 |
| HSR 基础属性 | `detail.stats` 最高突破档 | Lv80 = `*_base + 79 × *_add`（与 miao baseAttr 一致）；显示生命/攻击/防御/速度/嘲讽/能量上限（`sp_need`）；不显示双爆 |
| HSR 总属性加成 | `skill_trees` `point_type:1`（恒 10 个）`status_add_list` | 按 property_type 累加，标签取数据 name，独立 `stat-grid` 栏置于附加能力后（SpeedDelta 为固定值，其余 ×100）；已加强角色取加强节点 |

| HSR 附加能力 | `skill_trees` `point_type:3`（恒 3 个） | `point_name/point_desc` + 节点图标，独立一栏 |
| HSR 忆灵技能 | `point_type:4/5` + `detail.memosprite` | 「忆灵技能」两级渲染（忆灵名+图标作子栏，其下按技能 `type_name` 分忆灵技/忆灵天赋，图标取 skill_trees 节点）；pt5 并入忆灵天赋；技能卡无图标标签；无忆灵时标题取节点 `point_name` |
| HSR 星魂 | `detail.ranks` | 序号按排序键 1~6（不用数据自带 id） |
| HSR 参数名 | `model/MiaoParams.js` ← miao `meta-sr/character/<角色>/data.json` 的 `talent.*.tables[].name` | 按「各级数值序列」比对（≥3 点、1e-6 容差）匹配，常量与占位名不参与；未匹配回退「属性 N」。**外部数据只在主要功能万不得已时读**（参数名 nanoka 侧完全没有），文本类一律不跨插件取 |
| HSR 描述数值 | `detail.skills[*].level` 等 | 取无星魂常规上限档（6/10/1）渲染 + `（Lv.N）` 标注；行迹/星魂单档不标注；加强技能按加强档案 level |
| HSR 相关效果 | 技能/忆灵/行迹/星魂对象上的 `extra` | 按名词 id 去重，单列「相关效果/规则术语」（同 GI refs 排布），已加强角色也取加强档案 extra |
| HSR 开拓者 | 条目名 `{NICKNAME}`（5 命途 × 2 性别） | 索引派生「开拓者·<命途>」，男女折叠；参数名查询键统一「穹·<命途>」 |
| HSR 角色加强 | `detail.enhanced['1']`（10 个，`list.enhance`） | 直接用加强数据替换旧内容：技能按 id 末 6 位、星魂按键、行迹按 treeKey/nodeKey 覆盖；`enhanced.descs` 不展示；加强档案无忆灵与基础属性 |
| ZZZ 评级 | `list.rank` / `detail.rarity`（数值） | 游戏用 S/A/B/C 而非星级 → `zzzRank(value, pageKey)` **按各页满档顺移**：角色/音擎/邦布/敌人/鸣徽 满档 4 → S/A/B/C；物品（含物品详情）满档 5 → S/A/B/C/D（进阶2/特化3/高阶4/传奇5 武备即 5 档）。`meta.rarity`（"三星"）只是抓取派生的目录名，仅兜底；索引层取 map.json 的 rarity 标签（已核与内部数值 100% 一致）；非评级值（"未分类"）不出字母 |
| ZZZ hero | `meta.images` / `list` / `detail` | 背景取影画第三阶段横版大图 `derived.mindscape.3`（退 .2/.1，**必须跳过 `_placeholder`**，否则退路失效；再退角色立绘大图 `icon`；三张全缺的新角色留空，不落占位、不拿 142×142 圆头像放大）。小方框 `chips` 7 项：属性（元素标签归一 火属性→火）/特性/攻击类型/阵营/性别（`partner_info.gender`，缺则 `detail.gender` 1男2女）/生日/身高 |
| ZZZ 属性表格 | `detail.stats` + `detail.level[6]` + `detail.extra_level[6]` | 7 项：生命值/攻击力/防御力/冲击力/异常掌控/异常精通/能量自动回复。生命/攻击/防御 = `trunc(基础 + 59×成长/10000 + 最高突破档累计)`（**生命值成长字段是 `hp_growth`**，不随其他键加 `_growth`）；冲击力等三项无成长字段；再叠加核心技满档的**固定值**加成；能量自动回复 = `(基础+加成)/100`（120→1.2）。百分比类加成属游戏内「加成」，见下条 |

| ZZZ 核心技强化 | `detail.extra_level`（1~6 = A~F，值为累计加成） | `stat-grid` 栏，含百分比类（1800→18%）；`基础能量自动回复`（prop 30501）÷100（36→0.36）；值为 0 的项不列（不出现「+0」）；段带 `inSkills` 标记 → 天赋子视图一并显示 |
| ZZZ 技能 | `detail.skill.<类>.description[]` | 5 类（basic/dodge/special/chain/**assist**，数据无 `core`）→ **每招式一张卡**（带 `desc` 与带 `param` 的条目按 name 配对），tag 为类别；图标取 desc 内嵌 `<IconMap:X>` 的 fieldPath，无则类别默认资源名（`Icon_Normal`/`Icon_Evade`/`IconRoleSkillKeySpecial`/`Icon_QTE`/`Icon_Switch`），并**内联渲染**（先转 `@@ATLAS_ICON` 占位、清洗后再换 `<img class="inline-icon">`，否则被 cleanMarkup 剥掉） |
| ZZZ 文本清洗 | desc / 公式行 | `{LAYOUT_CONSOLECONTROLLER#A}{LAYOUT_FALLBACK#B}` → 取 FALLBACK（设备同义文案）；`{CAL:表达式,倍数,小数位}` → `AvatarSkillLevel(k)` 代入（恒等于本类别当前等级），倍数 100 表示小数比例，**仅引用等级的才补 `（Lv.12）`**；`{Skill:<id>,Prop:<n>}` → 行值 `main + growth×(Lv-1)`，复合公式走自写递归下降求值器（不用 eval / new Function） |
| ZZZ 资料 | `detail.partner_info.profile_desc` | 装成 `stories` 段，但**默认视图过滤掉**（待米三家资料重建）；`#角色故事` 子视图仍可取 |

**技能参数表**（`skillParams.js`，转置渲染）：`headers:['属性','Lv1'…]`，行=属性、单元格=段数组（数值/符号/单位分开，模板逐段 `.param-seg` + `<wbr>` 软换行）。
- GI：默认仅保留 Lv9-14（先按全 15 级判固定属性再抽样），`allLevels` 出全等级；跨级同值列抽为 `fixed[]`（技能卡上小格）。原始数据 `s.promote[level].param`，行名取 `desc[]` 中 `|` 前文本。
- HSR：`s.level[level].param_list`（无标签），列名走 MiaoParams，数值格式由描述 `#N[fmt]%` 推断；默认 `onlyVarying` 裁掉各级同值参数（秘技等全常量技能不出表）；天赋视图以常规上限收末尾 7 档（普攻/忆灵 7、战技类 12、秘技 1），倍率视图 `allLevels` 全等级。
- ZZZ：技能等级上限 12（5 类别的 `material` 表均 1~12 档）。技能视图取**末尾 7 档单表**（同 HSR 天赋视图口径，走 `params.rows`，模板标题「属性」）；倍率视图用 `paramsAll` 全 12 档单表，由 `applyRatesView` 每 5 列拆续表（`splitTableColumns` 与 HSR 共用）。不随等级变化的行（「能量消耗 20点」等）入 `params.fixed` 小格。
- 素材归属：角色素材栏只在 `materials` 子视图输出（默认视图与其它子视图都不含），由 `applyMaterialsView` 按游戏重建。

**素材口径**：三游戏武器/角色素材只聚合突破（晋阶）与技能/天赋类材料，**不含升级经验**（GI 武器 `xp_requirements`、ZZZ 音擎 `level[].exp` 均不折算；HSR 光锥无经验字段）——nanoka 页面会把音擎经验并入素材，故数字更大。HSR 行迹按「全解锁+全满级」计（含 pt3/pt1 一次性解锁），nanoka 只算技能升级部分（符玄信用点 2197500 vs 本插件 3000000）。素材来源：GI `detail.materials`、HSR `stats[].cost` + `skill_trees.*.material_list`、ZZZ `detail.level[].materials` + `skill.*.material` + `passive.materials`；名称/图标走 `model/itemIndex/`（gi/hsr 直查 map.json + 图标直拼，zzz 按需读 localPath）。武器类页面素材栏标题：GI 升级材料 / HSR 晋阶材料 / ZZZ 突破素材。

**素材排序**（`components/sections/materials.js` 的 `sortMatItems`，三游戏共用）：**货币 → Boss·周本素材 → 其余素材**，组内按物品 id **数值**升序。货币 gi `202` / hsr `2` / zzz `10`；Boss·周本段位 gi `113xxx`（rank4 世界 Boss / rank5 周本）、hsr `241` 命运的足迹 + `1104xx`(Boss)/`1105xx`(周本)、zzz `100941`「仓鼠笼」访问器 + `1100xx`(核心技进阶)/`1105xx`(高维数据)。角色 / 武器 / 邦布养成素材与**怪物掉落栏**同一口径（旧的手写 12 类别 `matSortOrder` 与绝区零素材栏的无排序行为都已删除）。必须按数值比较：字符串比较会把「105 好感经验」排到「113090」之后。注意原神 id 升序下同类相邻但**星级不全局单调**（怪物素材按系列分段：破损面具1星/污秽2星/不祥3星 → 沉重号角2星/黑铜3星/黑晶4星），星铁同样如此（116xxx 之后跳到 181010 陨铁）。
